# v2.0.3 — S1 黄金场景术语表

## 1. 文档目的与适用范围

本文档建立 v2.0.3 S1 黄金用户场景的统一术语体系，使未阅读任何外部资料的读者能够准确理解：

1. 新闻如何从 Inbox 进入 Intake。
2. 系统如何识别新闻的来源、重复情况及版权相关信息。
3. Disposition 如何表达处理判断，以及它与 Archive 的区别。
4. 经授权的新闻如何归档并形成 Traceable Knowledge。
5. Provenance 如何支持全流程追溯。
6. Local-first、Drive-backed、幂等重跑、故障可恢复等概念如何限定 S1 的行为语义。

**本文档是概念定义文件，不是产品设计、技术架构或实现方案。**

### S1 场景基准

本文档统一采用以下场景：

用户部署 Engine，将一篇新闻放入 Inbox。系统自动发现该新闻，进入 Intake 处理过程，识别来源、检查重复情况、判断版权相关条件，形成可查询的处理记录。系统依据处理判断进入 Disposition；只有符合授权条件的内容才能进入 Archive。最终形成可追溯的知识记录，使用户能够了解内容的来源、处理判断和归档结果。

该段是术语定义的共同语境，不代表所有新闻都必然归档成功。

### 范围规则

- 只定义与 S1 输入、处理、判断、归档、追溯直接相关的概念。
- 可以定义概念之间的关系，但不得规定具体实现机制。
- 不得将"自动处理"解释为"自动获得版权授权"。
- 不得将"可查询记录"等同于"已归档内容"。
- 不得将"来源已识别"等同于"来源可信"。
- 不得将"内容未重复"等同于"可以合法归档"。
- 不得把候选术语中的技术约束直接提升为必须实现的功能承诺。

## 3. 核心流程与对象

### G01 — 收件区（Inbox）
**中文名：**收件区
**英文名：**Inbox
**一句话定义：**用户放入待处理新闻的入口区域。
**与 S1 的关系：**用户将新闻放入 Inbox，启动后续自动发现和接入处理流程。
**易混淆辨析：**Inbox 是内容进入系统的入口，不等于 Intake 的处理过程，也不等于已完成归档的 Archive。

### G02 — 接入处理（Intake）
**中文名：**接入处理
**英文名：**Intake
**一句话定义：**对发现的新闻进行识别、检查并形成处理信息的过程。
**与 S1 的关系：**新闻被发现后进入 Intake，执行来源、重复和版权相关检查。
**易混淆辨析：**Intake 负责处理和获取判断依据；Disposition 负责形成后续处置判断。两者不得合并为同一概念。

### G03 — 处理裁定（Disposition）
**中文名：**处理裁定
**英文名：**Disposition
**一句话定义：**根据处理结果决定新闻后续处置方式的判断。
**与 S1 的关系：**系统在 Intake 之后依据来源、重复及版权相关信息判断新闻如何处置。
**易混淆辨析：**Disposition 是处置判断，不等于 Archive 的归档行为；分类可以体现处理判断，但不能替代全部裁定含义。

### G04 — 归档（Archive）
**中文名：**归档
**英文名：**Archive
**一句话定义：**在满足授权条件后保存新闻相关内容的行为。
**与 S1 的关系：**新闻经过处理裁定并符合授权条件后才能进入归档环节。
**易混淆辨析：**Archive 表示归档行为，不代表内容已被证明真实、来源可信或具备无限制使用权；未归档对象仍可有处理记录。

### G05 — 来源（Source）
**中文名：**来源
**英文名：**Source
**一句话定义：**新闻内容所归属或来自的发布主体或出处。
**与 S1 的关系：**系统在来源识别过程中判断新闻来自何处，为后续裁定提供依据。
**易混淆辨析：**Source 回答"内容从哪里来"；Document 回答"正在处理哪份内容"。一个来源可以对应多篇文档。

### G06 — 文档（Document）
**中文名：**文档
**英文名：**Document
**一句话定义：**作为独立对象接受处理的一篇新闻内容。
**与 S1 的关系：**用户放入 Inbox 的新闻是被发现、检查、裁定和可能归档的对象。
**易混淆辨析：**Document 不等于 Source；同一来源可发布多个文档，同一篇文档也可能存在不同修订内容。

### G07 — 来源与处理沿革（Provenance）
**中文名：**来源与处理沿革
**英文名：**Provenance
**一句话定义：**记录内容从何而来及经历何种处理的可追溯信息。
**与 S1 的关系：**贯穿新闻被发现、处理、裁定和归档的过程，使后续查询能够追溯其来历及处理结果。
**易混淆辨析：**Source 只描述来源；Provenance 同时关注来源及后续处理沿革。对象级报告是这些信息在单个对象上的可查询呈现，不构成独立阶段。

### G08 — 可追溯知识（Traceable Knowledge）
**中文名：**可追溯知识
**英文名：**Traceable Knowledge
**一句话定义：**能查询内容来源、处理过程及结果的知识记录。
**与 S1 的关系：**新闻处理后形成可查询记录，用户能够了解其来源、裁定及归档结果。
**易混淆辨析：**Traceable Knowledge 不等于已归档新闻全文；可追溯性要求记录能解释内容的来历和处理情况，并不保证内容绝对正确。

## 4. 运行原则与处理行为

### G09 — 本地优先（Local-first）
**中文名：**本地优先
**英文名：**Local-first
**一句话定义：**以本地环境作为内容处理与控制的优先基础。
**与 S1 的关系：**约束用户部署 Engine 后对新闻进行接入处理和控制的总体方式。
**易混淆辨析：**Local-first 不等于完全离线，也不排斥 Drive-backed；它强调本地优先，而非禁止外部存储。

### G10 — 云端存储支撑（Drive-backed）
**中文名：**云端存储支撑
**英文名：**Drive-backed
**一句话定义：**由 Drive 提供存储支撑，但不代表所有处理均在云端进行。
**与 S1 的关系：**描述新闻处理及归档场景中可能存在的 Drive 存储支撑关系。
**易混淆辨析：**Drive-backed 不是"全部数据必须上传 Drive"，也不代表新闻只要进入 Drive 就已完成授权归档。这里的 Drive 指 Google Drive 云端文件存储服务。

### G11 — 自动发现（Automatic Discovery）
**中文名：**自动发现
**英文名：**Automatic Discovery
**一句话定义：**系统无需用户逐篇手动触发即可发现待处理新闻。
**与 S1 的关系：**用户将新闻放入 Inbox 后，系统自动识别有待处理内容。
**易混淆辨析：**自动发现仅表示发现待处理对象，不等于 Intake 已完成，更不等于已经做出归档裁定。

### G12 — 内容指纹（Content Fingerprint）
**中文名：**内容指纹
**英文名：**Content Fingerprint
**一句话定义：**用于辅助识别内容相同或差异的内容特征标识。
**与 S1 的关系：**在检查新闻重复情况时，内容指纹可作为辅助判断依据。
**易混淆辨析：**指纹是用于比较的特征标识；去重是依据比较结果进行判断的过程。指纹一致不应被解释为版权许可一致。

### G13 — 去重（Deduplication）
**中文名：**去重
**英文名：**Deduplication
**一句话定义：**判断新闻是否与已有内容重复的过程。
**与 S1 的关系：**在 Intake 阶段判断新闻与已有对象的重复关系，为 Disposition 提供信息。
**易混淆辨析：**去重不等于直接删除重复新闻，也不等于忽略其处理记录；重复内容仍可具有不同来源及处理沿革。

### G14 — 修订对账（Revision Reconciliation）
**中文名：**修订对账
**英文名：**Revision Reconciliation
**一句话定义：**核对内容修订前后的差异及其对应关系。
**与 S1 的关系：**当新闻存在修订版本时，用于理解已处理内容与修订内容之间的关系。
**易混淆辨析：**修订对账关注同一内容的前后变化；去重关注内容是否重复。S1 单篇新闻首次处理不要求必然发生修订对账。

### G15 — 来源识别（Source Identification）
**中文名：**来源识别
**英文名：**Source Identification
**一句话定义：**判断新闻内容来自何处的过程。
**与 S1 的关系：**在 Intake 阶段识别新闻来源，支持后续处理裁定及来源追溯。
**易混淆辨析：**来源识别是判断行为，Source 是所判断的来源；识别来源不代表验证了该来源的真实性或可靠性。

### G16 — 版权识别（Copyright Identification）
**中文名：**版权识别
**英文名：**Copyright Identification
**一句话定义：**识别新闻内容的版权及使用限制相关信息。
**与 S1 的关系：**在 Intake 阶段识别版权相关条件，为后续归档授权判断提供依据。
**易混淆辨析：**版权识别不等于获得授权；无法确认版权条件不等于默认允许使用。

### G17 — 权利感知处理（Rights-aware Processing）
**中文名：**权利感知处理
**英文名：**Rights-aware Processing
**一句话定义：**在内容处理及归档判断中考虑版权和授权约束。
**与 S1 的关系：**系统在 Disposition 与 Archive 之间必须考虑授权限制，避免将不满足条件的内容视作可直接归档。
**易混淆辨析：**版权识别用于识别相关信息；Rights-aware Processing 是依据相关约束处理内容的原则。两者不可互相替代。

### G18 — 幂等重跑（Idempotent Rerun）
**中文名：**幂等重跑
**英文名：**Idempotent Rerun
**一句话定义：**重复执行同一处理时不产生不应重复的结果。
**与 S1 的关系：**当同一篇新闻被再次处理时，重复执行不应无故形成重复的归档成果。
**易混淆辨析：**幂等重跑关注重复执行的结果一致性；去重关注不同输入或已有内容间的重复关系。幂等不等于禁止再次执行。

### G19 — 故障可恢复（Failure Recoverability）
**中文名：**故障可恢复
**英文名：**Failure Recoverability
**一句话定义：**处理发生中断后能够恢复并继续形成可追溯结果。
**与 S1 的关系：**当新闻处理流程意外中断时，后续恢复不应使其来源、处理判断和归档结果失去可追溯性。
**易混淆辨析：**故障可恢复不等于保证从不出错，也不等于保证任何故障都能自动修复；幂等重跑关注重复执行，故障可恢复关注中断后的继续处理。

## 5. 易混淆术语辨析

| 辨析对象 | 语义边界 | 不允许的等同关系 |
|---|---|---|
| Inbox / Intake | 入口区域 / 接入处理过程 | 放入 Inbox = 已处理完成 |
| Intake / Disposition | 获取与检查信息 / 形成后续处置判断 | 检查完成 = 处置已批准 |
| Disposition / Archive | 是否以及如何处置 / 实际归档行为 | 允许归档 = 已完成归档 |
| Source / Document | 来源主体或出处 / 被处理内容对象 | 一个来源 = 一篇文档 |
| Source / Provenance | 内容来自何处 / 内容来源及处理沿革 | 已知来源 = 全程可追溯 |
| Provenance / Traceable Knowledge | 追溯信息 / 可查询的知识记录 | 有来源字段 = 完整可追溯知识 |
| 指纹 / 去重 | 比较依据 / 重复判断过程 | 指纹存在 = 去重完成 |
| 去重 / 修订对账 | 重复关系 / 修订前后关系 | 内容变化 = 必然是新文档 |
| 版权识别 / Rights-aware | 识别权利相关信息 / 遵守权利约束处理 | 识别版权 = 获得授权 |
| Local-first / Drive-backed | 本地优先原则 / 云端存储支撑 | Drive-backed = 云端优先 |
| 幂等重跑 / 故障可恢复 | 重复执行语义 / 中断恢复语义 | 可重跑 = 任意故障可恢复 |
| Archive / Traceable Knowledge | 归档行为 / 可查询追溯结果 | 未归档 = 不存在处理记录 |

## 6. S1 场景术语串联

以下以一篇新闻为例，按 S1 顺序串联术语。

用户将一篇新闻放入 **Inbox（收件区）**。系统通过**自动发现（Automatic Discovery）**识别到有待处理内容，该新闻作为一篇 **Document（文档）** 进入 **Intake（接入处理）**。

在 Intake 阶段，系统执行**来源识别（Source Identification）**，判断该新闻的 **Source（来源）**；通过**内容指纹（Content Fingerprint）**辅助进行**去重（Deduplication）**，判断是否与已有内容重复；同时执行**版权识别（Copyright Identification）**，获取版权及使用限制相关信息。上述处理信息连同来源一起构成该文档的 **Provenance（来源与处理沿革）**。

系统随后进入 **Disposition（处理裁定）**，依据来源、重复及版权相关信息判断新闻的后续处置方式。在此过程中遵循**权利感知处理（Rights-aware Processing）**原则，确保不满足授权约束的内容不被视作可直接归档。

### 路径 A：符合授权条件

若新闻满足授权条件，系统执行 **Archive（归档）**，保存相关内容。处理完成后形成 **Traceable Knowledge（可追溯知识）**，用户可查询该新闻的来源、处理过程及归档结果。整个过程遵循 **Local-first（本地优先）** 原则，**Drive-backed（云端存储支撑）** 可为归档提供存储支撑。

### 路径 B：授权条件不满足或无法确认

若授权条件不满足或无法确认，新闻**不得**被描述为已授权归档。但系统仍保留该文档的处理记录与裁定结果（包括来源、去重判断、版权识别结果），形成可查询的 **Provenance** 信息。**Traceable Knowledge** 依然存在——它记录的是"该新闻因授权不足未归档"这一可追溯事实，而非归档成功的结果。

### 条件性说明

- **修订对账（Revision Reconciliation）**：仅当该新闻存在修订版本时，才需要核对修订前后的差异。单篇新闻首次处理不涉及此步骤。
- **幂等重跑（Idempotent Rerun）**：若同一篇新闻因故被再次送入处理流程，重复执行不应产生重复的归档记录。
- **故障可恢复（Failure Recoverability）**：若处理过程中发生中断（如系统重启），恢复后应能继续形成完整的可追溯结果，不丢失已有的来源与处理信息。

## 7. 范围与非目标

本文档明确不包含以下内容：

1. 不规定数据模型。
2. 不规定文件结构或目录布局。
3. 不规定接口、事件或任务执行机制。
4. 不规定具体去重算法、指纹算法或版权判断算法。
5. 不规定故障恢复技术。
6. 不规定权限授予流程。
7. 不保证所有新闻都可合法归档。
8. 不将术语定义解释为对应功能已实现。
